# 口播稿规则与硬校验

## 结构

- 用 `scripts/视频脚本_版本A.md` 保存带章节标题的版本：
  `**第N章: 标题**`（N 用 一、二、三…），标题独立成行且不进 TTS。
- 正文按章节连写，通篇像一个人娓娓道来，不要大纲、不要 Markdown 符号。
- 常规长片 3000–5000 汉字（每章 ≥400）；短版/社交片 1200–2500 汉字也可以，
  但每一章仍要成段、不断章。

## 固定开场与结尾（一字不差）

- 第 1 章 hook 一两句之后必须出现：
  `欢迎回来，我是言同学。`
  全片只能出现这一次。
- 结尾固定句：
  `今天的故事先讲到这,你顺手点的一个关注赞,是对我极致的肯定,有更新你会第一时间收到提醒,我是认真讲故事的言同学,咱们下期再见~`
  （结尾句用半角逗号亦可，但整句字符必须一致。）

## 数字与标点

- 年份一律中文数字，且用「零」不用「〇」：`2024` → `二零二四`，
  `2006` → `二零零六`。**交 TTS 前对 chapters.json 检查 `〇`，有则替换为 `零`。**
- 型号/非年份数字按口语转中文，例如 `MINI EV` 拆字母、`LZ 110` 写成
  `LZ 一一零`；正文中英文/数字之间保留一个空格。
- 禁止破折号 `—`、连字符 `-`、下划线 `_`、括号 `()`，一律用逗号或句号。
- 正文不要出现 `第N章` 字样和任何标题句。

## 去 AI 味

写完必须人工过一遍以下“AI 壳”，发现即改写：

- 二元对比壳：不是 A 而是 B / 不仅是 A 更是 B / 与其说 A 不如说 B
- 路标连接词：值得注意的是、总而言之、由此可见、首先…其次…最后、通过…方式
- 空洞断言：本质上、核心在于、底层逻辑、真正重要的、这个世界需要…
- 规整排比/段落等长/每段“观点+解释+总结”；结尾不要空喊口号式反问

改写手法：删过渡、长短句交错、给具体细节（年份/动作/画面），保留观点与事实，
不编造数据。

## 切分与校验

```powershell
python <skill>\scripts\parse_script.py <项目目录>
```

产物：`scripts/视频脚本_版本A_clean.md`、`scripts/口播流水_版本B.txt`、
`audio/chapters.json`。校验要点：

- 章节数、每章字数符合目标；
- 纯口播文本开头 100 字内含开场白；
- 以结尾句收尾；
- 无标题行/无括号/无破折号残留；
- 无 `〇`。
