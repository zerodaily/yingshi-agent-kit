# Retro Narration Video（复古口播讲解视频）

把「选题或口播稿」做成一条复古纸墨风的中文口播视频，可同时产出横屏 1920×1080
与抖音竖屏 1080×1920 两个版本。本流程不再依赖 NotebookLM 出 PPT 或在线图片
模型：画面统一用「研究 → 文案 → 本地配音 → 本地出图 → HyperFrames 合成」。

## 适用与不适用

- 适用：言同学等账号的知识/人物/社会话题口播；已有口播稿需要出片；把旧流程
  的题材重做成“每一画面都有一张复古配图”的版本。
- 不适用：需要真实拍摄/既有录像素材剪辑；需要 AI 视频模型做镜头动画；纯 PPT
  幻灯片且无口播。

## 产线总览

```text
① 选题研究(web/笔记) → ② 口播稿(硬规则自动校验) → ③ IndexTTS2 分章配音(自愈)
→ ④ 词级转写 → ⑤ 配图库复用 + Z-Image 批量出图 + ESRGAN 放大
→ ⑥ HyperFrames 复古合成(横屏) → vertical_transform 一键转竖屏
→ ⑦ check+渲染 → ⑧ 60秒引流片段 + 竖屏套图/交付
```

## 关键规则（踩过坑，勿跳）

1. 年份一律用「零」不用「〇」：`二〇二四` 会让 TTS 读错，写成 `二零二四`、
   `二零零六`。生成后必须对 chapters.json 全局检查 `〇`。
2. 口播稿正文禁止出现章节标题、Markdown 符号、括号与破折号；正文里的章节头
   只用于视觉标题，绝不能进 TTS。
3. 第 1 章 hook 后必须一字不差出现：
   `欢迎回来，我是言同学。`
   结尾必须一字不差以固定句收尾（见 script-rules）。
   > **与抖音钩子规则的衔接（必读）**：抖音版要求"前3秒必须是炸弹钩子，
   > 禁止用欢迎语开头"——两条不冲突：顺序永远是 **炸弹钩子 → 欢迎语**。
   > 即第一句抛钩子，第二句一字不差接"欢迎回来，我是言同学。"，两个版本
   > 都按这个顺序写，TTS 和字幕都用同一份口播稿。
4. 文字/排版页不得交文生图模型渲染：AI 只画“画面内容”，文字全部由 HTML/CSS
   叠在卡片上，保证字形清晰。
5. 本地 Z-Image 在 2080 Ti 上用 512×512、4 步；单张约 20–50 秒。不得直接跑
   768+ bf16 全精度（实测单张 >20 分钟）。放大交给 Real-ESRGAN。
6. 每个画面必须有一张配图；配图统一套用同一风格前缀与同一调色，禁止混入
   实拍、异风格图片或纯文字页。
7. HyperFrames：文字元素用 `class="clip"` 直挂 root；不要给视频包一层带
   `data-start` 的容器；中文字体必须用 `@font-face src: local()` 声明。
8. 渲染用 `--quality draft --low-memory-mode --gpu`，TEMP/TMP 指到大盘
   （如 `D:\workspace\tmp\...`），避免 C 盘爆盘。

## 每个画面的版式约定

- 米黄旧纸底（`#f2e8d3` 系）+ 颗粒纹理 + 双线/朱红点缀；大标题楷体（KaiTi）、
  正文宋体（SimSun）。
- 内容结构：上方一张 `artplate` 配图（朱红木框画卡），下方 HTML 文字。
- 一段 5 分钟口播约 20 个画面；若时长更长，按 2–3 秒/画面节奏扩张，不要复用
  同一张图做相邻两个画面。

## 抖音优化规则（2026-09 新增，必守）

基于抖音汽车知识类爆款调研，以下规则直接影响完播率和推流。

### 脚本结构
1. **前3秒必须是炸弹钩子**：禁止用"欢迎回来我是言同学"**作为第一句**。顺序固定为
   "钩子 → 欢迎语"（见上文"开场白规则衔接"）：先用最炸的数字/反差/揭秘抓住人，
   第二句一字不差接"欢迎回来，我是言同学。"
   - 错误："欢迎回来，我是言同学，今天我们来讲迈凯伦F1"
   - 正确："1998年它跑出391km/h，这个纪录保持了12年，法拉利都追不上。欢迎回来，我是言同学。"
2. **钩子5选1**（每集至少用1个）：数字冲击 / 反常识 / 揭秘式 / 情绪共鸣 / 对比反差。
3. **每章开头埋小钩子**：不要平铺直叙讲历史，每章开头先抛一个悬念或结论。
4. **结尾加行动召唤**：最后10秒必须有一句引导互动，如"你觉得这台车值不值？评论区聊聊"。
5. **每5秒一个信息点**：避免长段平铺，情绪要有起伏，像过山车。

### 竖屏安全区排版
6. **抖音安全区**：顶部10%、底部25%、右侧10%会被UI遮挡。核心内容（图+主文字）必须放在中间安全区（高度15%-70%）。
7. **字幕位置**：不要贴底部！放在画面中间偏下（约60%-65%高度处），避开底部点赞按钮。
8. **字号加大**：竖屏标题≥76px，正文≥44px，85%的人静音刷抖音，必须一眼看清。
9. **言同学IP位置**：固定在右下角安全区内，不要太大抢主角。

### BGM节奏
10. **前3秒BGM直接起**：不要淡入，钩子那句话的同时重音落下。
11. **关键数字加重**：说到核心数字（如391km/h、106台）时BGM短暂停顿或加重。
12. **章节切换加翻页音效**：配合复古纸墨风，用翻报纸/翻书音效。

### 内容拆分（额外交付物）
13. **每集额外剪1条60秒引流片段**：从5章里挑最炸的那个点，配强钩子开头，单独发抖音引流。
14. **长视频引流逻辑**：短片段发抖音引流量 → 引导看主页完整长视频（B站/西瓜）。

## 封面设计规范（2026-09-28 新增，必守）

### 言同学标准IP形象（每次封面必须出现！）
- **外貌**：黑框方眼镜（不是圆眼镜！）、黑色短卷发/炸毛、山羊胡+上唇小胡子
- **穿着**：黑色短袖T恤、深色牛仔裤、白色帆布鞋
- **风格**：木刻版画风格，深绿色单色线条，和整体画风统一
- **要求**：必须和车有互动动作（坐车上看书、靠车门、蹲车头修车、站车顶眺望、指车讲解），不能只是站在旁边当装饰
- **大小**：占画面约1/4到1/3，要醒目但不抢车的主角地位

### 配色规范（不能搞反！）
- **背景**：米黄旧纸色 #f2e8d3，带撕裂/卷边/磨损边缘
- **主色**：深绿色 #2d5a3d（标题、车身、人物线条）
- **点缀**：朱红色方形印章"言同学"，做旧磨损效果，放右下角
- ❌ 禁止深绿色背景+米白字！那是反的

### 4种排版模板轮换（不要每次都一样！）
每次做封面时从下面4种里选一种，或者混搭，保证系列感但不单调：

1. **经典款（日产模板）**：顶部巨字品牌名（深绿，占顶部1/3）→ 横线+英文副标题 → 车+言同学互动在中间 → 右下角红印章
2. **左图右文款**：左侧2/3画面是车+言同学，右侧1/3竖排品牌名+副标题，印章在左下角
3. **沉浸款**：言同学和车占满整个画面，品牌名小一点放在顶部角落，印章放右下角
4. **对比款**：上下或左右分屏，老车vs新车，言同学在中间指着两边，品牌名放中间

### 错误示例（禁止出现）
- ❌ 封面没有言同学，只有车和文字
- ❌ 深绿色背景+米白字（配色反了）
- ❌ 每次都是顶部大字+中间车的同一种排版
- ❌ 言同学戴圆眼镜、没有胡子、穿别的衣服

## B站发布流程规范（2026-09-29 新增，必守）

**禁止再用Playwright脚本自动发布！** 有风控风险，全部改用Browser Use操作用户自己的Chrome浏览器，和真人操作无差别。

### Browser Use发布操作步骤（严格按顺序，不要跳步）
0. **先查草稿箱余量**：B站草稿箱硬上限 30 条。打开创作中心 → 内容管理 → 草稿箱，
   数一下当前草稿数；≥28 条时先停下来告诉用户手动发布/删除旧稿腾位置，
   不要等到上传一半才发现传不上去。
1. 保持浏览器窗口宽度≥1200px，窄窗口会导致封面弹窗布局错位
2. 打开B站上传页，上传横屏final.mp4（上传是异步的！不用等上传完成，传完文件句柄立刻继续下一步）
3. **立刻去传封面**：封面优先级最高，等封面弹窗加载3秒后，用`input[accept*='image']`上传4:3 png封面；弹出"是否同步4:3到16:9"弹窗时点"确认同步"，自动完成16:9封面，不用单独再传一次
4. 填标题、标签，填简介：**简介框也按placeholder="填写更全面的相关信息"精确定位contenteditable，不要用最后一个元素瞎找**
5. **铁律：先向下滚动找到"更多设置"，它默认是折叠的！必须先点击展开，再操作里面的内容，否则下面填的所有内容都不生效——这一步每次必须做，不许跳过**
6. 在展开的更多设置里：
   - 创作声明选"含AI生成内容"
   - 互动设置勾选"开启精选评论"（用文本查找label元素点，不要靠坐标）
   - **粉丝动态必写（不能漏！）**：100字以内，简短有趣，结合本期内容写一个车迷共鸣的小问题/冷知识/钩子，引导评论互动。**必须通过placeholder="有趣的动态描述"文本精确定位contenteditable元素，填完后JS读取innerText验证内容真的存在，再点存草稿**
7. 点"存草稿"，不要点"立即投稿"，用户自己最后点发布

**发布前一键校验**：点存草稿之前，把 `scripts/bilibili_publish_verify.js`
粘贴到浏览器控制台运行，8 项全 PASS 再提交（标题/简介/标签/封面/更多设置
展开/粉丝动态/字数/创作声明）。

### 踩过的坑
- ❌ 更多设置默认折叠，不展开直接往下填粉丝动态=白填
- ❌ B站标签不要逗号不要#号，每个标签单独一行，用户直接整段粘贴，B站会自动按回车逐个添加
- ❌ contenteditable的div（简介、粉丝动态）用普通type输入无效，必须用JS设置innerHTML+dispatch input事件
- ❌ 封面只需要传一次4:3，之后点同步弹窗自动覆盖16:9，不用传两次
- ❌ B站封面用png格式，用`input[accept*='image']`选择器上传，**绝对不要用通用`input[type=file]`，会选到视频上传input把封面当视频传错！**
- ❌ 封面弹窗刚打开时input还没渲染出来，立刻传会报错，等3秒再传
- ❌ 操作过程中不要触发页面跳转，否则会弹"确定要离开吗"确认框打断流程
- ❌ 找输入框不要用eds[最后一个]，必须按各自独有的placeholder文本精确定位，否则会找错元素白填

## 脚本去AI味规则（2026-10-04 新增）
写完口播稿后必须按以下规则去AI味，再进TTS：
1. 删掉所有"值得一提的是""总而言之""综上所述""不仅...而且"这种书面AI套话
2. 把长句拆成短句，每句不超过15个字，像真人聊天一样说话
3. 加口语化语气词："你想想""说实话""很多人不知道""我跟你说"
4. 不要全是客观陈述，加入主观判断和情绪："这台车当时真的离谱""谁能想到呢"
5. 删掉所有对仗工整的排比句，AI最爱写这个，真人说话不会这么整齐
6. 允许小的逻辑跳跃和口语停顿，不要每段都结构完美

## 涨粉引导内容结构优化（2026-10-04 新增）
针对B站/抖音/视频号三个平台，脚本结构必须按这个来：
1. **开头3秒强钩子**：第一句就抛悬念/反常识/痛点，比如"这台车当年被美国人骂成垃圾，结果现在成了全世界的神车"
2. **系列化追剧感**：开头加"言同学汽车帝国系列第X集"，结尾必须留"下一集我们讲XX，关注我别错过"
3. **结尾涨粉引导（固定结构）**：
   - 讲完最后一个知识点，加1个互动问题引导评论："你开过这台车吗？评论区聊聊"
   - 加1个关注理由："这个系列我会把全世界经典车都讲一遍，点关注追更不迷路"
   - 不要说"喜欢请点赞投币收藏"这种空话，直接给观众关注的理由：你关注了能看到什么后续内容
4. **评论区引导**：故意留一个小争议点/小错误，吸引车迷来评论区纠正/辩论，提升互动率
5. **BGM和节奏**：每6-8秒切一个画面，不要一个画面停10秒以上
6. **结尾固定话术（一字不差）**：
   "好了，今天的故事就到这里。我是言同学，我们下辆车再见。"
   后面接："对了，你最想让我讲哪台车？评论区告诉我。"
7. **粉丝动态**：每条视频的粉丝动态都写一个车迷共鸣的钩子，比如"有没有小时候坐过这台车的？举个手"
